# Работа с FormaPanel в браузере через Home Assistant

Первая установка: 31.10.2026; актуализировано 01.11.2026.
Среда: Studio Code Server + FormaPanel Workshop 0.1.1 внутри HA.
Полная карта: [начать разработку](../development.md),
[компоновка файлов](../04-architecture/source-composition.md),
[операционный runbook сборки](../06-validation/build-and-preview-runbook.md).

## Начало работы

1. Открыть **Studio Code Server** из бокового меню HA.
2. Открыть папку `/config/esphome/formapanel-rh01` или лежащий в ней
   `FormaPanel.code-workspace`. Это полный Git checkout проекта.
3. Редактировать YAML, изображения, шрифты и общие пакеты прямо в этой папке.
4. Открыть **FormaPanel Workshop**, выбрать профиль и нажать
   **Обновить предпросмотр**, **Проверить** или **Собрать прошивку**.
5. После сборки переключать кадры основной/общей страницы, состояния лампы
   или скачать Factory/OTA BIN. Установка на устройство выполняется отдельно.

Оба приложения используют одни файлы на HA. Экспорт, импорт и копирование
прошивки между ними не нужны. Мастерская автоматически создаёт только короткий
служебный entry wrapper с путями cache/assets, а ESPHome разрешает настоящие
`packages` и `!include` из checkout.

## Где менять настройки

| Назначение | Путь в репозитории |
|---|---|
| Список доступных сборок | `config/workbench-targets.json` |
| Настройки демо гостиной/спальни | `firmware/esphome/profiles/living.yaml`, `bedroom.yaml` |
| Общий основной экран, шрифты и картинки | `firmware/esphome/packages/rh01-ui.yaml` |
| Общая дополнительная страница | `firmware/esphome/packages/info-page.yaml` |
| Входы для физических устройств | `firmware/esphome/targets/` |
| Входы для настоящего LVGL preview | `firmware/esphome/previews/` |
| GPIO, дисплей, touch, backlight | `firmware/esphome/boards/guition-s3-480.yaml` |

RH-01 сохранён как исходный одностраничный вариант по референсу. Два новых
демо-профиля используют общий home layout и общую страницу «Информация»,
но разные значения спальни/гостиной. На устройстве общая страница открывается
долгим нажатием на лампу. Для совершенно другой главной страницы профиль может
подключить другой home-пакет или применить точечный `!extend`, сохраняя общие
ресурсы и дополнительные страницы. Реальные HA entity bindings пока не заданы.

## Предпросмотр

Это запуск общего ESPHome/LVGL кода на host, а не интерпретация YAML в JavaScript.
Он выдаёт кадры после настоящей отрисовки LVGL. Шрифты, PNG, RGB565, alpha и
дополнительные страницы берутся из того же проекта.

Снимки обновляются по кнопке после сохранения файлов. При изменении исходников
старые кадры помечаются «Изменения ещё не собраны». Переключение кадров в браузере
не управляет освещением и не отправляет команды на панель.

Мастерская выполняет одну задачу за раз, чтобы несколько сборок не конкурировали
за память HA. Изолированные build cache и артефакты находятся в приватном `/data`
приложения; source checkout доступен сборщику только для чтения. Перезапуск HA
для обычного редактирования/сборки не требуется.

## Добавление варианта устройства

1. Добавить `profiles/<имя>.yaml` с настройками комнаты. Для изменения только
   значений подключить `rh01-shared.yaml`, как делают гостиная и спальня.
2. Добавить `targets/<имя>.yaml`: уникальное ESPHome имя, аппаратный пакет,
   connection/diagnostics и новый комнатный профиль.
3. Добавить `previews/<имя>.yaml`: уникальное имя host, тот же профиль и
   `room-backend.yaml`. Аппаратный пакет сюда не включать.
4. Добавить пару firmware/preview entry в `config/workbench-targets.json`.
   Обновить страницу Workshop: перезапуск приложения для нового профиля не нужен.
5. Выполнить проверку, native preview и сборку BIN нового варианта.

Для другой главной страницы создать отдельный home-пакет и подключить его
в новом профиле вместе с общим `info-page.yaml`. Общий RH-01 home-пакет при
этом не подключать второй раз. Текущий контракт общей страницы и capture
backend использует ID `rh01_home`, `rh01_lamp_button`, `rh01_lamp_image`,
`rh01_lamp_on`, `rh01_lamp_off` и `panel_info`: новый home должен сохранить
эти точки подключения либо получить свой capture backend и адаптер навигации.
Пути к общим PNG/TTF продолжают задаваться `formapanel_asset_dir`.
Так вторичные страницы и ресурсы остаются общими при разных композициях home.

## Git и GitHub

В Source Control доступны diff, commit, ветки и Synchronize Changes. Репозиторий
связан с `https://github.com/exceptioncpp/FormaPanel.git`. При первоначальной
настройке перенесена история и текущие изменения; автоматический push не делался.
Текущий рабочий набор содержит незакоммиченные изменения разработки.

Git-панель включается для доверенной папки проекта. Доверие FormaPanel включено
после явного подтверждения пользователя; весь `/config` для этого не требуется.
Для первого Push Studio Code может запросить вход в GitHub. Файлы доступа или
ключи с Windows в редактор не переносились. Изменения коммитятся и отправляются
после просмотра diff, без безусловного pull/push по таймеру.

После начала работы на HA обновлять другие checkout через Git. Старые
`reports/local/build_ha.py deploy` и bootstrap helpers относятся к первоначальной
подготовке: не использовать их для перезаписи уже редактируемой папки.
Локальные `secrets.yaml` исключены из Git; BIN содержат provisioned credentials
устройства и скачиваются через аутентифицированный HA Ingress.

## Визуальные редакторы

Установленный ESPHomeDesigner RC48 не открывает каталог ESPHome с зависимостями
как репозиторий: его импортер не раскрывает `!include`, а preview `lvgl_img`
ограничен. Поэтому он не включён в обязательный цикл. В нём можно отдельно
исследовать UI-фрагмент, затем применить выбранные изменения к файлу пакета с
проверкой Git diff и native preview. Это не перенос всей прошивки.

ESPBoards также требует отдельного UI-импорта/экспорта и не заменяет редактор
checkout. Native LVGL Pro / SquareLine / EEZ предполагают другую исходную модель
(XML/project/C), поэтому переход на них — отдельное решение, не скрытый этап
работы с ESPHome YAML.

[проверку установленной среды](../06-validation/ha-workshop-2026-10-31.md),
