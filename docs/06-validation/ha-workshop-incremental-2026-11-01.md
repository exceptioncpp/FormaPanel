# Workshop 0.1.1: инкрементальное обновление UI

Проверено 01.11.2026 на существующей HA VM. ESPHome 2026.10.1 / LVGL 9.5.0
сохранены. Исправление затрагивает только локальную Workshop: HA Core,
Device Builder и физические устройства не перезапускались/не прошивались.

## Причина и изменение

В 0.1.0 основной wrapper создавался заново в `/data/jobs/<id>/entry.yaml`.
ESPHome не находил прежние compatibility metadata возле нового entry и
очищал общий build tree. Наличие одного build_path не сохраняло incremental
сборку: в реальном RH-01 job было 571 compile steps и 41.71 с.

В 0.1.1 wrapper имеет постоянный путь `/data/configs/<kind>-<profile>.yaml`.
`ESPHOME_DATA_DIR=/data/esphome/<kind>/<profile>` сохраняет metadata отдельно
для каждой операции и профиля. Snapshots, logs и скачиваемые файлы остаются
уникальными в `/data/jobs/<id>`; source checkout остаётся read-only для worker.
Первый запуск после миграции наполняет metadata заново: он занял 43.15 с и
в последующие цифры не включён.

## Реальное измерение

| Сценарий | Server job, с | Compile steps | Очистка build | Native PNG |
|---|---:|---:|---|---:|
| Та же композиция без изменения UI | 6.19 | 0 | Нет | 2 |
| Часы перемещены с x=29 на x=31 в общем rh01-ui.yaml | 7.88 | 3 | Нет | 2 |
| Исходное x=29 восстановлено | 6.64 | 3 | Нет | 2 |

Это полная серверная задача validate + compile + запуск native + PNG,
а не только время компилятора. Polling браузера во время задачи добавляет
до 2 с до появления кадра; сеть и ручное нажатие сюда не включены.
Другая машина, новые fonts/images или изменение build config могут дать
большее время. Обещания субсекундного YAML hot reload нет.

Изменение было подтверждено содержимым изображений: diff ограничен часами,
bounding box `(32, 103)–(219, 156)`. После возврата координаты итоговый PNG
побитно совпал с исходным. Временная правка отменена; исходники сверены
с manifest. Дополнительный regression test проверяет сохранение metadata
между jobs и изоляцию профилей, операций и snapshot directories.
Все 11 тестов проекта проходят.

Локальное доказательство: игнорируемый файл
`reports/local/workbench-smoke/incremental-benchmark-2026-11-01.json`;
job IDs: `1793484448894-rh01`, `1793484544288-rh01`, `1793484555914-rh01`.
Секреты и firmware BIN в этот документ не включены.

## Что это даёт пользователю

Сохранить YAML в Studio Code Server, выбрать профиль и нажать «Обновить
предпросмотр» в Workshop. Кадр и журнал обновятся сами после запуска задачи.
Автоматический запуск по Save и постоянный интерактивный host ещё не
реализованы. Новая страница требует своего capture-сценария; worker пока
не обходит произвольные страницы автоматически.
