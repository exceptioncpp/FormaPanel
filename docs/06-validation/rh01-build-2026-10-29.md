# RH-01 — сборка на Home Assistant, 2026-10-29

## Среда и область изменений

Фактически проверено: Home Assistant OS в VM200, Home Assistant Core **2026.10.4**,
ESPHome Device Builder **2026.10.1**, контейнер `app_5c53de3b_esphome`.
Установка дополнительных приложений и SDK на Windows не потребовалась.
Перед сборкой на HA было доступно около 45 GiB диска и 2.8 GiB RAM,
дополнительно 1.2 GiB swap.

Рабочая конфигурация: `/config/esphome/formapanel-rh01.yaml`.
Она включает копию исходников из
`/config/esphome/formapanel-rh01/firmware/esphome/formapanel-rh01.yaml`
и задаёт `formapanel_asset_dir: formapanel-rh01/assets`.
Относительные `!include` сохраняют структуру репозитория.
Секреты находятся только на HA в выделенном подкаталоге пакетов:
существующие Wi-Fi credentials использованы без изменения,
API-ключ и OTA-пароль созданы отдельно для FormaPanel.
При повторной доставке они сохраняются.

Существующие конфигурации Guition и термостатов не изменялись.
Перезапуск HA, прошивка USB и OTA не выполнялись.

## Воспроизведение

Локальный приватный помощник `reports/local/build_ha.py` использует SSH alias
`home-pve` из инфраструктурного `local/keys/ssh_config`, затем
`qm guest exec 200` и существующий контейнер Device Builder.
Он копирует YAML, пять RH-01 PNG и два локальных Nunito TTF,
проверяет конфигурацию и собирает образ на HA.

```powershell
python reports/local/build_ha.py deploy
python reports/local/build_ha.py verify
python reports/local/build_ha.py validate
python reports/local/build_ha.py compile
python reports/local/build_ha.py fetch
```

Эквивалентная команда сборки внутри HA:

```sh
docker exec -e ESPHOME_IS_HA_ADDON=true -e ESPHOME_ESP_IDF_PREFIX=/data/cache/idf app_5c53de3b_esphome esphome compile /config/esphome/formapanel-rh01.yaml
```

Длительные команды запускаются асинхронно через QEMU guest agent;
состояние проверяется `qm guest exec-status 200 <pid>`.
Сборка **не запускает** `esphome run` или `upload`.
Переменные окружения нужны для использования `/data/build` и уже установленного
toolchain из `/data/cache/idf`; обычный `docker exec` не наследует переменные,
которые init приложения добавляет только процессу Device Builder.

## Проверки

- ESPHome `config`: **успешно**, код завершения 0.
- Локальные проверки репозитория: **7 тестов успешно**, отдельный validator также успешен.
- Browser preview: сохранены реальные screenshots состояний on/off;
  изменяется только область лампы, bounding box `(381, 361)–(463, 438)`.
  Это проверка preview в браузере, не снимок framebuffer LVGL на устройстве.
- ESPHome `compile`: **успешно**, код завершения 0, ESP-IDF **5.5.6**.
  Финальная инкрементальная сборка выполнена после повторной доставки исходников;
  SHA-256 всех 12 YAML/PNG/TTF на HA совпадают с локальными файлами.
- Статическая оценка сборки: RAM **112 667 / 341 760 bytes (33.0%)**,
  flash **1 588 863 / 8 126 464 bytes (19.6%)**; app partition имеет 80% запаса.
  Это не измерение свободной RAM/PSRAM после запуска LVGL.
- Factory/OTA BIN созданы на HA, загружены на Windows;
  SHA-256 каждого локального файла совпадает с соответствующим файлом на HA.
- Проверка реального дисплея, touch, RAM/PSRAM, Wi-Fi/API и OTA: не выполнялась.
  Успешная сборка сама по себе не подтверждает аппаратную совместимость ревизии платы.

Локальные результаты сохраняются в игнорируемом Git каталоге
`reports/local/firmware/`; `manifest.json` содержит размеры и SHA-256.
`source-manifest.json` содержит SHA-256 всех доставленных исходников и ресурсов.
Журналы очищаются от значений известных credentials; полный развёрнутый YAML
после успешной проверки не сохраняется.

После сборки контейнеры HA Core и Device Builder проверены: оба `running`,
свободно 43.7 GiB диска и около 2.8 GiB RAM available.

Сборщик предупреждает об использовании GPIO19/20, связанных с USB Serial/JTAG,
и рекомендует encryption вместо password для OTA. Сборку это не блокирует;
для проверки на плате сохраняется требование сверить её ревизию и аппаратную схему.

## Откат

Сборка не меняет прошивку устройства. Для отмены подготовленной конфигурации
достаточно убрать только выделенный wrapper и каталог `formapanel-rh01`;
существующие YAML и общий `secrets.yaml` восстанавливать не требуется.
Build cache нового узла находится в `/data/build/formapanel-rh01`
внутри приложения Device Builder и не используется существующими узлами.
