# ADR-0004 — браузерная мастерская ESPHome внутри HA

Дата: 31.10.2026. Решение: принято по выбору пользователя.

## Требование

Редактировать многофайловые ESPHome/LVGL прошивки в браузере, хранить исходники
в Git/GitHub, собирать несколько профилей на общих ресурсах. Ручной экспорт
или импорт всей прошивки между редактором и сборщиком неприемлем.
Среда размещается внутри существующего Home Assistant, без SDK на Windows.

## Решение

Один checkout `FormaPanel` находится в общем каталоге конфигурации HA.
Studio Code Server открывает его для редактирования и Git. FormaPanel Workshop
читает этот же каталог через read-only mount, запускает ESPHome на настоящих
входных YAML и хранит только cache/результаты в своём `/data`.

```text
GitHub ↔ Git checkout в HA ← Studio Code Server в браузере
                   │
                   ├─ target YAML → ESPHome → Factory / OTA BIN
                   └─ host YAML → ESPHome + LVGL → снимки экранов
```

В основе preview — официальный ESPHome `host` + `snapshot` display. Общий
UI-пакет, растровые ресурсы и TTF компилируются тем же ESPHome, что и прошивка.
Различаются только аппаратный и host входные файлы. BMP конвертируется в PNG
без изменения композиции. Это настоящее выполнение LVGL на сервере;
аппаратные RGB timings, физический LCD, touch и PSRAM проверяются отдельно.

Мастерская открывается через HA Ingress; дополнительных сетевых портов,
Docker socket, Supervisor API и доступа к USB у неё нет. Конкурирующие сборки
сериализуются. Показываются Git branch/commit/dirty, хеш исходников и признак
устаревшего preview после сохранения новых изменений.

## Многофайловая структура и варианты

ESPHome сам обрабатывает `packages`, `!include`, substitutions и ID merge.
Мастерская не реализует собственный парсер всей прошивки и не превращает
проект в один редактируемый файл. Короткий служебный wrapper задаёт только
путь к общим assets и отдельный build directory, затем включает реальный
входной YAML из checkout. Он создаётся автоматически, не содержит UI.

В `config/workbench-targets.json` объявлены профили и пары device/preview entry.
Каждый профиль выбирает собственную главную страницу или её параметры,
подключая общие ресурсы и вторичные страницы. Build cache и результаты
профилей разделены. Секреты локальные, игнорируются Git и не используются
host-предпросмотром. Бинарники с provisioning остаются за HA-аутентификацией.

## Почему не ESPHomeDesigner как основной редактор

Установленная версия `1.0.0-rc.48` обрабатывает `!include` как строковый тег,
не раскрывая файловое дерево проекта. Её `lvgl_img` показывает placeholder,
а импорт/обратный экспорт покрывает подмножество LVGL. ESPBoards также требует
подготовленного UI-фрагмента вместо открытия всего checkout. Поэтому оба
остаются отдельными инструментами для экспериментов, а не обязательной частью
цикла разработки. Полноценный визуальный редактор, напрямую сохраняющий нашу
структуру ESPHome, в этой проверке не найден.

Git не синхронизируется безусловно по таймеру. Пользователь делает Commit,
Pull и Push в Studio Code Server, видя diff и конфликты. Это сохраняет
контроль над публикацией и не перезаписывает незавершённые изменения.
